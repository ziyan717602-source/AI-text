# 从已有小说提取 chapter_intent 的指令

## 用途

从一本已有小说的某一章中，提取出轻量级的"章意图"（chapter_intent.yaml）。
这个意图模拟的是**人类作者在写这一章之前脑子里想的东西**，而不是写完之后的分析。

## 使用方式

将下方的「提取指令」连同一章原文一起发给 LLM，即可得到 chapter_intent.yaml。

---

## 提取指令

```
你是一个小说写作助手。我将给你一章小说的原文，请你从中提取出这一章的"写作意图"。

注意：你要模拟的是作者在写这一章之前脑子里想的东西，不是写完之后的分析。
不要包含任何"作者运用了什么手法"之类的分析性语言。
不要包含任何具体的描写细节或对话内容。
只提取"这一章要完成什么"的骨架级意图。

输出格式严格遵循以下 YAML 结构：

chapter_id: {章节编号，如 ch001}
title: {章节标题}

goal: {2-4 句话，说明本章要完成什么叙事目标}
  - {目标1}
  - {目标2}
  - ...

must_include: {本章必须出现的事件/场景/信息点，3-6 项}
  - {事件1}
  - {事件2}
  - ...

must_not_reveal: {本章绝对不能提前揭示的信息，1-3 项}
  - {禁区1}
  - {禁区2}
  - ...

state_change: {本章结束时相对于开头发生了什么状态变化}
  character: {主要角色名}
  before: {本章开始时的状态}
  after: {本章结束时的状态}

tone: {1-2 句话描述本章的整体气质/情绪基调}

pov: {视角角色名}
```

## 示例输出

```yaml
chapter_id: ch001
title: 平凡的开始

goal:
  - 建立男主"普通但有点实用主义/凉薄"的底色
  - 引入女配李笑颜，展示修行世界的冰山一角
  - 引入玉之灵，完成草率拜师，开启被迫修炼

must_include:
  - 银行取钱看余额（体现穷和普通）
  - 餐厅遇到李笑颜被推销魔法仪式，男主敷衍拒绝并逃单
  - 小树林里玉佩发声，诱导男主拜入紫罗峡门下
  - 烈日下被迫跑三万米，展现"被迫修炼"的荒诞感

must_not_reveal:
  - 紫罗峡的历史和完整传承
  - 玉之灵的真实身份和来历

state_change:
  character: 刘得宜
  before: 普通大学生，浑浑噩噩度日
  after: 拜入紫罗峡门下，被迫开始跑步修炼

tone: 日常里带一点荒诞，男主不热血，是被迫的

pov: 刘得宜
```

---

## 注意事项

1. **不要写"怎么写"**：intent 只管"写什么"，不管"怎么写好"。不要出现"用短句""用动作代替心理描写"之类的写作指导。

2. **不要写场景拆分**：intent 不负责拆场景。拆场景是 Planner Agent 的工作。intent 只描述"这一整章要完成什么"。

3. **must_not_reveal 是防剧透的关键**：这一项要从"全书大结局/后期反转"的角度思考——这一章里绝对不能提前露馅的东西是什么？

4. **state_change 要具体**：不要写"男主成长了"，要写"男主从不知道玉之灵存在 → 知道玉之灵存在并拜入紫罗峡"。

5. **tone 要有区分度**：不要写"紧张刺激"这种万能词。要写出这一章区别于其他章的独特气质，如"日常里带荒诞""压抑中透着温情"。

---

## 批量提取指令（一次提取 3 章）

如果你要一次性提取连续 3 章的 intent，可以追加这段：

```
我将给你连续 3 章的小说原文。请分别提取每一章的 chapter_intent.yaml。
注意：
- 第 2 章的 state_change.before 必须等于第 1 章的 state_change.after
- 第 3 章的 state_change.before 必须等于第 2 章的 state_change.after
- 三章的 must_not_reveal 应该逐步收紧（第 1 章可以暗示的，第 2 章可能需要更明确但仍不揭示）
- 每章的 tone 应该有变化，体现叙事节奏

请分三次输出，每次用 --- 分隔。
```
