## 四、信息管理的最终做法

### 1. 角色文件必须拆层

不要再做一张“全角色卡”。

每个角色至少拆成四份：

#### public.md

只放**读者在当前进度可以知道**的内容。
例如：

* 外貌
* 表层身份
* 常见习惯
* 明面关系
* 已公开经历

#### hidden.md

只放：

* 身世真相
* 后续动机
* 反转
* 伏笔真实含义
* 只有规划阶段能看的设定

#### voice.md

只放人物声纹：

* 常用句型
* 禁用词
* 情绪上升时的变化
* 对不同人说话口气差异
* 典型动作/停顿习惯

#### state.json

只放当前状态：

* 当前地点
* 当前知道什么
* 当前不知道什么
* 当前关系热度
* 身上物品
* 伤势/体力
* 当前目标

这样做的意义是：**Writer 不需要角色一生，它只需要“这一场可见的身份 + 当前状态 + 说话方式”。**

### 2. 剧透控制必须前置到文件层

不要靠 prompt 里写一句“不要剧透”。

你要在文件结构上强制隔离。
最低标准：

* `public.md` 永远允许写作读取
* `hidden.md` 默认禁止 Writer 读取
* 只有 Planner 可读 hidden
* Planner 只把“本场允许暴露的信息”写进 packet

也就是：**剧透过滤发生在 packet 构建阶段，而不是生成阶段。**
这正是你材料里反复提到的“披露状态标记”“渐进式披露”“scene brief/scene packet”的真正落点。 

### 3. 时间线和伏笔用 YAML，不用自然语言自由发挥

建立两个核心文件：

`events.yaml`

```yaml
- id: ev_001
  chapter: 1
  scene: 1
  summary: 顾临第一次见到沈砚
  participants: [顾临, 沈砚]
  place: 南街药铺
  revealed_facts:
    - 沈砚懂药理
  state_changes:
    - 顾临对沈砚的警惕 +1
```

`unresolved_threads.yaml`

```yaml
- id: hook_001
  introduced_at: ch001_s01
  content: 沈砚袖口有旧血迹
  known_by_reader: true
  known_by_protagonist: false
  resolved: false
  planned_payoff_arc: arc02
```

Writer 不更新它们。
**Observer/State Updater 更新。**

## 五、真正该做的工作流

## 最终推荐：4 Agent，但不是“4 个都很重”

### Agent 1：Planner / Scout

输入：

* 本场细纲
* 当前章目标
* 当前 POV
* 角色 public/state/voice
* 必要世界设定
* 相关未回收伏笔
* 上一场结果

输出：

* `scene packet`

这是最关键的 Agent。
它不是用来写文的，而是用来**裁剪上下文**。

### Agent 2：Writer

只做一件事：
**把 packet 写成初稿。**

它不能看全库，只能看 packet。
它也不要背“去 AI 味”太多任务，只保留基本硬约束。

### Agent 3：Auditor

不改文，只打报告。
检查四件事：

* 设定冲突
* 时间线冲突
* 剧透/越界披露
* AI 味与口吻漂移

输出 `audit.json`。

### Agent 4：Patch Rewriter

只处理 Auditor 标出来的段落。
不允许重写全章。
不允许改剧情，只允许做局部表达修订。

这就是你上传材料里最有价值的轻量四段式，我建议直接采用，不再改架构。

## 七、去 AI 味的最终方案

这里最容易走偏。
我的最终建议是：

### 1. 不做“大润色”，做“三段式去 AI 味”

#### 第一层：写前防 AI

在 `global_style.md` 和 `forbidden_patterns.md` 里写死：

* 禁止总结性句尾
* 禁止空洞心理分析
* 禁止用抽象词替代动作
* 禁止高频套话
* 禁止平均段落长度过于整齐
* 禁止每段都“起-承-转-收”过度工整

#### 第二层：写时控 AI

给 Writer 注入的不是“如何写得漂亮”，而是：

* 少解释
* 多动作和反应
* 对话带信息差
* 避免全知旁白替读者理解
* 一段只推进一个焦点

#### 第三层：写后杀 AI

Auditor 只找这些问题：

* 黑词黑句式
* 段落节奏过匀
* 对话人声纹混同
* 抽象词密度高
* 解释句占比过高
* 明明能写动作却写成结论

Patch Rewriter 只针对命中段落改写。

### 2. skills 只保留三层

你原来的分层思路是对的，但要收敛成：

#### 层 1：硬约束层

全书共用。
例如：叙述人称、语体、禁忌句式、禁止总结升华。

#### 层 2：场景层

例如：

* 对话场
* 冲突场
* 暧昧场
* 调查场
* 写景场
* 回忆场

一次只启一个主模块。

#### 层 3：技法层

例如：

* 降解释量
* 对话去书面腔
* 用肢体细节承接情绪
* 压低形容词密度

不要再往下拆。
拆太细会把写作变成模板流水线。你上传材料里已经明确提醒了“层级过深导致 prompt 组装复杂，按需加载才是关键”，我赞同这个判断。 

### 3. 一定要加“风格锚点”

每类场景准备 2–5 段你认可的人类文本。
不要长，300–800 字就够。

例如：

* 冷对话样本
* 暧昧拉扯样本
* 动作追逐样本
* 压抑氛围样本

Writer 和 Patch Rewriter 都能用这些样本对齐。
这比抽象地说“写得更有文学性”有效得多。你材料里也明确把“风格锚点/写作样本”列为去模板感的重要措施。

```json
}
```
**CC执行逻辑**：写第15章时，CC读取此JSON，代码逻辑过滤掉 `revealed_at_chapter > 15` 的秘密，只截取 `chapter <= 15` 的最新状态，从而**物理隔绝后续剧透**。

---

### 二、 消除AI味：节拍表 + 负向约束 + 局部Patch

不要让AI“直接写正文”，必定满是“不禁、然而、瞳孔骤缩”。采用**“骨-肉-皮”三步走**。

#### 1. 骨：剧情节拍表
让LLM先把细纲转化为极简的动作流。
*   **Prompt核心**：`将细纲转化为节拍表。只写动作和事件结果。禁止任何心理描写、环境描写和修辞。`
*   **产出**：`1.林墨推门。2.看到李清雪倒地。3.长老偷袭。4.林墨吐血。5.强行催动太虚诀反杀。`

#### 2. 肉：场景扩写
根据节拍，结合**动态加载的Skill**扩写。
*   **技能包路由设计 (`/skills/`)**：
    *   `fight.md`: 动作短句切分，多用动词，少用形容词。
    *   `dialogue.md`: 潜台词写法，用动作神态代替“说”。
*   **负向约束（最有效去AI味）**：在System Prompt中加入绝对禁令：
    > `禁用词汇：不禁、竟然、倒吸一口凉气、瞳孔骤缩、值得注意、总而言之。禁用句式：不是...而是...、过渡解释内心活动。规则：每段最多3句，长短句必须交替。`

#### 3. 皮：独立审计与局部修订
**绝对不要全章润色**，全章润色等于全章重写，会丢失原意且越改越平庸。
*   **Auditor Agent**：只审查，不改文。输出结构化报告。
    > `检查：1.是否有设定冲突 2.是否有违禁AI词 3.是否有超过3句的排比/总结段落。输出JSON：[{"paragraph": 3, "issue": "包含违禁词'不禁'", "action": "rewrite"}]`
*   **Patcher Agent**：只根据审计报告，**精准重写第3段的那个词/句**。

---

### 三、 工作流编排：CC 下的 4 步标准流水线

在 CC 中，你可以将以下流程写成一个 Python/Shell 脚本，或者直接用自然语言让 CC 按步骤执行。

**Step 1: 编译场景简报**
*   **动作**：CC 读取 `/outlines/ch15.md`，读取相关 `/state/*.json`，过滤掉未来章节信息。
*   **输出**：生成一个纯净的上下文包 `scene_packet.json`。

**Step 2: 盲写初稿**
*   **动作**：CC 调用 Claude Sonnet API，输入 `scene_packet` + 节拍表要求 + 场景Skill + 负向约束。
*   **输出**：`/drafts/ch15_draft1.md`。此时剧情是对的，但可能仍有残留AI味。

**Step 3: 独立审计**
*   **动作**：CC 调用更便宜的模型（如 Haiku），带上违禁词表和设定库审查草稿。
*   **输出**：`/audits/ch15_audit.json`，列出需要修改的精确行号和原因。

**Step 4: 定向Patch (Patch Rewriter)**
*   **动作**：CC 读取草稿和审计报告，仅针对标红段落调用 Sonnet 进行局部重写。
*   **输出**：`/drafts/ch15_final.md`。

**Step 5: 状态回写**
*   **动作**：CC 让 LLM 提取最终稿中的状态变化（如：林墨受伤了），自动更新 `/state/lin_mo.json`，供下一章使用。

### 四、 MVP 验证计划（请在CC上执行的第一步）

不要一上来写完整平台，先用 CC + 几个本地文件跑通一个极简闭环。

**验证目标**：用3章的细纲，测试“防剧透”和“去AI味”是否有效。

**执行步骤**：
1.  手动建一个文件夹，写入2个角色的 `.md` 和 `.json`（带上章节锁）。
2.  写一个 `global_rules.md`（包含Top 10最恶心的AI禁词，要求长短句交替）。
3.  找一段现成小说的细纲（约3000字剧情）。
4.  在 CC 中输入指令：
    > `读取细纲和角色JSON（过滤第2章以后的信息），先输出动作节拍表；然后根据节拍表和global_rules扩写正文；最后审查正文是否包含禁词，如有则局部替换。`
5.  **人工评估**：读一读，有没有剧透？有没有“倒吸一口凉气”？阅读节奏是否紧凑？

**如果这3章跑通了，说明底层逻辑成立，后续所有的开发（GUI、自动化状态回写、RAG检索历史章节）都只是工程量问题。**

### 总结

你选择 **CC + Claude API** 是极具优势的，因为 CC 具备极强的本地文件操作和逻辑编排能力。

1. **信息管理靠代码过滤，不靠大模型自觉。**（用JSON+章节号锁死真相）
2. **去AI味靠禁令和局部修补，不靠全章润色。**（先定骨架，再上禁令，最后定点排雷）

### 核心架构原则（The CC/LLM Paradigm）

1. **信息隔离原则（防剧透）**：绝不全量喂入设定，依靠脚本做“切片投喂”。
2. **反向约束原则（去AI味）**：不要教AI“怎么写得美”，而是严厉规定“绝对不能怎么写”。
3. **写审分离原则（保下限）**：写作模型只管剧情，审计模型负责挑错，重写模型只做“局部微创手术”。

### 模块一：小说信息管理落地指南（混合本地文件流）

在CC所在的本地项目目录下，建立一套刚性的文件结构。**Markdown管静态设定（人类可读），JSON管动态状态（机器易读）。**

#### 1. 目录结构设计
打开终端，让CC为你创建以下结构：
```text
/NovelProject
 ├── /01_Lore          # 静态世界观与人物档案 (.md)
 ├── /02_State         # 动态真相库 (.json)
 ├── /03_Skills        # 风格与技法约束库 (.md)
 ├── /04_Outlines      # 细纲与规划 (.md)
 ├── /05_Drafts        # 章节成稿目录
 └── /scripts          # CC需要调用的Python/Node自动化脚本
```

#### 2. 防剧透的角色卡片设计（信息打标）
在 `/01_Lore/characters/主角.md` 中，必须使用**条件标签**隔离信息。
```markdown
# 角色档案：林墨

## 公开属性 (始终加载)
- 外貌：黑发黑瞳，常穿洗得发白的青衫。
- 性格：谨慎、对危险直觉敏锐。

## 隐藏设定 (受控加载)
- [reveal_chapter: 15] 真实身份：前朝遗孤。
- [reveal_chapter: 30] 隐藏动机：接近女主是为了寻找玉佩。
```

#### 3. 动态状态更新（JSON真相库）
创建 `/02_State/current_state.json`。这个文件由AI在每章写完后自动提取并更新，绝不让人工维护：
```json
{
  "current_location": "云澜宗外门",
  "inventory":["残破铁剑", "神秘玉简"],
  "relationships": {"苏清寒": "警惕，欠对方一个人情"},
  "pending_hooks": ["玉简发光的原因", "后山传来的异响"]
}
```

#### 4. 运行时上下文编译（Context Builder）
**执行动作**：在 `/scripts` 下写一个简单的 Python 脚本 `build_context.py`。
当你要写第5章时，CC会运行这个脚本：
1. 提取第5章的细纲。
2. 读取角色 `.md`，**通过正则过滤掉 `[reveal_chapter: >5]` 的所有行**（物理级防剧透）。
3. 读取 `current_state.json` 转换为简洁文本。
4. 将这三者拼接成一个 `scene_packet.md`（场景简报），作为接下来生成正文的唯一参考物。

---

### 模块二：根治“AI味”的落地指南（负向约束+定向微创）

AI味的核心来源是：大模型倾向于使用统计学上的高频词（如“不禁”、“宛如”、“某种程度上”），且习惯用总结性的话语代替具体动作。

#### 1. 建立《绝对违禁词库》 (Negative Constraints)
在 `/03_Skills/banned_style.md` 中建立黑名单。
```markdown
# 写作绝对禁令（Highest Priority）

1. 【禁用词汇黑名单】：
   - 严禁使用：不禁、宛如、仿佛、某种程度上、不可否认、深吸一口气、瞳孔骤缩、值得一提的是、嘴角勾起一抹弧度。
2. 【禁用句式】：
   - 严禁使用“不是...而是...”的排比句。
   - 严禁使用“这标志着”、“这意味着”等总结性评价。
3. 【生理反应禁令】：
   - 严禁描写空洞的生理反应（如：心脏猛地一跳、倒吸一口凉气）。改为具体的物理交互（如：他捏碎了手里的茶杯）。
```

#### 2. 引入风格锚点（Few-Shot 样本）
在 `/03_Skills/style_anchor.md` 中，**放入你自己写的、或者你非常喜欢的名家小说的 3-5 段文字。**
在Prompt中告诉AI：“仔细分析以下文本的句长方差、动词使用频率和叙事节奏，你的输出必须与该文本的文风指纹完全对齐。”

#### 3. “三权分立”的写作管线（告别一次成文）
这是最重要的一步。在CC中，不要用一个Prompt出结果，而是通过脚本串联三个LLM API调用：

*   **Writer（写手，如 Claude 3.5 Sonnet）**：
    *   **输入**：`scene_packet.md` + `banned_style.md` + `style_anchor.md`。
    *   **指令**：只关注把剧情写出来，严格推进事件，不准自我发挥加戏。
*   **Auditor（审计员，如 GPT-4o-mini 或 Claude 3 Haiku）**：
    *   **输入**：Writer生成的初稿。
    *   **指令**：你是一个严厉的编辑。检查文本中是否出现了违禁词？是否有一眼AI的排比句？是否角色的位置和JSON状态库冲突？
    *   **输出**：JSON格式的报错报告（如：`[{"paragraph": 3, "error": "使用了违禁词'不禁'"}, ...]`）。
*   **Reviser（修补匠，如 Claude 3.5 Sonnet）**：
    *   **输入**：初稿 + 审计报告。
    *   **指令**：**只重写报错的段落！只重写报错的段落！**（Spot-fix）。保持其他段落一字不改。

### 模块三：基于 CC 的最小可行性（MVP）执行路径

不要一上来就写复杂的管理平台。今天晚上你就可以在终端里用 Claude Code 跑通第一段测试。

#### 第一步：准备测试物料
1. 找一本你喜欢的小说，提取其连续 3 章的细纲（每章约3-5个场景，明确动作和对白）。
2. 在本地建立好上述的目录结构。

#### 第二步：配置 Claude Code 的 `CLAUDE.md`
在项目根目录创建一个 `CLAUDE.md`，这是CC的系统级指令，赋予CC编排者的身份：
```markdown
# 角色定义
你是一个高级小说工作流编排器。你的任务不是直接写小说，而是调用 /scripts 下的脚本，并调度 LLM API 来完成流水线作业。

# 工作流指令
当我说“开始撰写第X章”时，你必须严格执行以下步骤：
1. 运行 `python scripts/build_context.py X` 生成本章的场景简报。
2. 提取简报，并结合 `/03_Skills` 中的禁令词库，生成 Writer 提示词，调用 LLM API 生成初稿并存入 `/05_Drafts/chX_draft.txt`。
3. 提示我进行人工确认。
4. 如果我确认无误，运行 `python scripts/extract_state.py` 提取剧情增量，更新 `/02_State/current_state.json`。
```

#### 第三步：跑通闭环
在终端输入：`claude 开始撰写第1章`。
1. **盯紧剧情一致性**：看生成的正文是否脱离细纲？JSON文件是否正确更新了角色的物品和状态？
2. **盯紧AI味**：看生成的正文中是否出现了黑名单里的词汇？如果有，立刻补充到 `/03_Skills/banned_style.md` 中。

#### 第四步：调优与扩展
当你用这种方式连续跑通 3 章，且剧情没有崩坏（第3章依然记得第1章获取的道具），AI味控制在可接受范围内时，你的 MVP 就成功了。

此时，你可以开始增加：
*   **伏笔回收系统**：在 JSON 里增加 `hooks` 字段，细纲里打上标记，让 Auditor 专门检查该章节是否处理了对应的 hook。
*   **简单的全文检索**：写一个脚本，将之前生成的所有章节用 SQLite 全文索引（FTS）存起来。遇到需要回忆的场景时，让 CC 先执行 `python search_history.py "某角色名"`，将结果注入简报。
